# Ask conversation continuity

Ask interprets a follow-up against the current chat, including the original request, recent exchanges, offered follow-ups, source references, prepared email and reply draft text, uncertainty, lookup candidate metadata, and actual action outcomes. Later restrictions and corrections take precedence. The currently open Gmail thread provides additional context rather than overriding the ongoing subject.

The extension sends at most ten complete exchanges (the initiating exchange and the newest nine for longer chats). Each message has up to 8,000 characters of prose and an optional 12,000-character assistant context field. The server retains the original user request and complete recent exchanges within a 64,000-character budget. This is bounded conversation context, not unlimited recall. Earlier source references are historical pointers; current claims must retrieve current evidence and citation labels.

The optional response `context` carries up to 8,000 characters of tool outcomes and lookup metadata. Read-only results retain identities, dates and reference handles, with bounded lists and strings; raw received email bodies, snippets, web text and saved note prose are excluded. Prepared drafts are already part of the response and remain available for revisions. No chat content or query is added to the server's persistent memory store.

Every Ask tool that prepares an email or changes mail declares its effect. Clients that send the `approval` feature (the side panel's Chat) never get a mail change executed from a model call: the change is proposed for the user to allow instead (see [chat permissions](chat-permissions.md)). Otherwise the tool receives a separate structured semantic review before execution. The review compares the proposed action with user intent, conversation constraints and current tool evidence. Missing user choices produce a tool result for the assistant to clarify in its own words and stop further effects in that request. An incorrect proposal with already clear user intent may be corrected without asking again. Invalid or unavailable review output prevents execution. Read-only tools still run concurrently; effects run sequentially. Reviews use existing interactive inference, budget accounting and provider configuration, adding one bounded inference call per proposed effect.

Retained chats resume until New chat is explicitly selected, rather than expiring after a 30-minute pause. The selected chat is saved per inbox, including an empty New chat. Switching inboxes clears in-memory turns before loading that inbox's history. History Off and Clear erase retained chat data and selection. A follow-up with conversation history goes through the agent rather than a keyword shortcut for the currently open thread.

Regression tests cover selected suggestions, retained and new chats, inbox isolation, long answers, reply draft revisions, original constraints, raw-text exclusion, action blocking, failed review output and correction of a mismatched proposal. Semantic cases for selective actions, ambiguous acceptance, draft selection and explicit bulk authorization are in `packages/server/src/evals/ask-conversation.test.ts` and require a real provider through `npm run eval:live`. Controlled tests do not establish real-model judgment or live Gmail behavior.
